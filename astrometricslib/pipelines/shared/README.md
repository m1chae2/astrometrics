# Shared pipeline tools

This folder holds code that more than one pipeline (astrometry, photometry, spectroscopy, asteroid detection, stacking) depends on. Nothing here runs on its own — it is called from inside a pipeline's own `pipeline.py`/`runner.py`/`batch.py`.

This folder sits below the five pipelines, so nothing here imports a specific pipeline (`pipelines/<name>/`), `pipelines/tasks.py` or `pipelines/target_batch.py`. When shared code needs a pipeline's function or class, the caller passes it in. `astrometricslib/test/test_layer_boundaries.py` enforces this. Code with only one pipeline as its user lives in that pipeline.

## What each file is for

- `analysis_context.py` — the shared container a pipeline run passes between its own stages: the loaded image, detected sources, and results found so far.
- `frame_grouping.py`, `frame_optics.py` — sort a target's frames by camera, optic, and role (light/dark/flat/bias), and work out which physical telescope or lens took a given frame.
- `frame_scanning.py` — finds image files on disk and reads them into frame records. It skips the output of processing: a file whose name contains `_stacked`, `starless`, `starmask` or `processed`, or whose header has a positive `STACKCNT` (Siril writes it only on a stack, and keeps `IMAGETYP = Light Frame` on it). The sorter files such a stack under `others`, not under the lights. Each record stores the file's size and modification time, and a re-index with `refresh_headers` does not open a file that still matches them.
- `quarantine_path.py` — the name of the `_excluded` folder where stacking moves frames with clouds or trailed stars, and the one test for "is this path inside it". Frame scanning skips that folder so moved frames do not rejoin the target.
- `previous_stack_path.py` — the name of the `_previous` folder where a restack keeps the stack it replaced. Frame scanning skips that folder so the old stack never counts as an input.
- `session_identification.py`, `target_sessions.py` — group a target's frames into observing sessions (one continuous night or run with the same setup), and figure out which stars an image sequence contains. `session_identification.py` takes the star identifier from its caller (the astrometry pipeline's `StarIdentifier`), typed as the `SessionStarIdentifier` protocol, which names the methods it calls. It also holds `write_wcs_to_fits_header`, which saves a solved WCS into a FITS header. It writes the SIP distortion terms with the sky map and deletes the sky-map keywords of any earlier solve first. When a frame is plate-solved during session identification, the result records the solver's fit residual RMS in arcseconds and its matched-star count; both are `None` when the sky map came from the file's own header or the solver returned no statistics.
- `camera_passes.py` — plans which cameras a batch run should process, and which targets go to each camera pass.
- `angles.py` — angle helpers. `wrapped_ra_difference_deg(ra1, ra2)` subtracts two Right Ascensions (RA, the east-west sky coordinate) and wraps the result into (-180, 180] degrees, so 359.9 and 0.1 are 0.2 deg apart. It accepts floats or arrays. Code that compares or searches around RA values calls it instead of subtracting, because RA wraps from 360 deg back to 0 deg. The asteroid detector and the astrometry star identifier use it.
- `catalog_star_identity.py` — decides whether two different catalog names refer to the same star. It also holds `CATALOG_MATCH_RADIUS_ARCSEC` (10 arcseconds), the largest distance between a detected star and a catalog entry for the two to count as one star. The astrometry star identifier and `star_recording.py` both use it.
- `star_recording.py` — the shared rule every pipeline uses to decide which stars are worth keeping, and how to save them to the star catalog.
- `applied_camera_profile.py` — records which camera profile (sensor characteristics, saturation threshold) a pipeline run actually used, on that run's quality summary.
- `target_center_hint.py` — turns a target's catalog right ascension/declination into a starting position hint for plate solving.
- `target_camera_index.py` — summarizes each target's light frames per configured camera: how many frames each camera took and the time of the newest one. The user interface's target list uses it to filter by camera and to sort by the most recently imaged. A camera writes its name into FITS headers in its own spelling (for example `Nikon DSLR DSC D5300`), so the module matches names to the configured camera names through `camera_identity`, which reads each camera profile's alternate spellings. `TargetCatalog.query(detail="camera_index")` calls its `build_target_camera_index`. A frame from a camera that is not configured still counts toward a target's newest frame time, but not toward any camera.
- `target_overview.py` — builds the short target records that `TargetCatalog.query` returns: one row per target (name, position, frame counts, cameras, last night imaged, whether it has a stack), and one target's record with its frames grouped by night, filter, exposure and camera and its quality summaries cut down to flags and headline numbers. It only reads, so looking at a target never marks it as changed.
- `target_records.py` — reads and writes `Target` records in the catalog database. `PROCESSED_IMAGE_EXTENSIONS` lists the endings of a finished picture (`.jpg`, `.jpeg`, `.png`, `.tiff`, `.tif`); `TargetCatalog.reindex_frames` makes such a file the target's processed image instead of a frame. A process keeps one object per target: a target handed out by `get` stays the object the catalog holds, so a job that edits it for minutes (a stack) still saves its edits. `list` reads the stored targets fresh and updates a held target in place only if it has no unsaved edits. A save writes only the targets that were touched and really changed since they were read or last saved, so a copy that was only looked at cannot overwrite another program's edit. `read_saved_target` reads one record straight from storage, to check what a save wrote.
- `star_catalog_queries.py`, `star_analysis.py` — answer `StellarCatalog.query`. They pick stars by ids, name, target, region or position, filter them (magnitude, spectra, photometry, a real catalog magnitude, spectral class, a search text), hide single-frame photometry detections (ids ending in `:Star_<n>`), sort them by id, by usefulness (spectra, then named stars, then photometry, then brightest first) or by spectrum match, and page them. They also count stars per spectral class and per target. A real catalog magnitude is a finite number of at least -2 that is not exactly 0 (`has_catalog_magnitude` in `models/stellar_source.py`); smaller values are instrumental magnitudes from photometry, and 0 means the catalog gave none. The per-star spectrum summary reports how close the best reference type is (`own_type_percent_off`, the relative RMS times 100), the gap to the second-best reference (`rms_gap_to_second_best`, in relative RMS units, a difference of two RMS values and not a probability), `is_ambiguous` (that gap is below `AMBIGUOUS_RMS_GAP`), `rms_gap_to_next_class` and `is_class_ambiguous` (the same test against the best reference of another spectral class), `no_good_match` and `differs_from_catalog`. All four limits come from `models/stellar_source.py`. The summary has no confidence or probability field.
- `star_overlay.py` — places a target's stars in pixels on its stacked image, for labels drawn over it. It projects each star's sky position through the image's world coordinate system (WCS, the FITS header block that maps pixels to sky positions) and keeps the stars that land on the image. When the image has no WCS, it uses the pixel center saved when each star was detected. Star clusters and `Star_<n>` field detections get no label.
- `stack_preview_path.py` — the file names of the stretched JPEG and stretched FITS saved next to each stack, and the JPEG quality. Stacking writes these files (`stacking/post_processing/stack_preview.py`) and the image viewer looks for them; both take the names from here so they cannot disagree.
- `simbad_object_types.py` — reads the object types (for example `V*` for a variable star) out of one row of a SIMBAD answer. The astrometry star identifier and the `scripts/backfill_simbad_object_types.py` script both use it, so both read an answer the same way.
- `star_kinds.py` — tells from a star id how the star can be looked up (Gaia DR3 id, a position-only `FIELD_J` id, and so on) and reads its stored position. The SIMBAD and variable-star backfill scripts share it.
- `variable_star_catalogs.py` — looks up stars in the AAVSO Variable Star Index (VSX) and in Gaia DR3 through CDS XMatch, a service that matches a whole table of positions in one request. A match must lie within `MATCH_RADIUS_ARCSEC` (3 arcseconds), and a Gaia match is ignored when its G magnitude differs from the star's by more than `MAXIMUM_MAGNITUDE_DIFFERENCE` (2.0). `scripts/backfill_variable_star_flags.py` uses it.
- `api_arguments.py` — checks the arguments of the public methods. `resolve_target` turns a target id into its `Target` after reading the stored targets again, so a target another program changed is seen.
- `image_conversions.py`, `image_scaling.py` — convert images between formats and adjust brightness/contrast for on-screen display. For a big frame, the display stretch measures the sky from a sample of the pixels (`measure_sky(..., sample_pixels=True)`), which gives the same picture in a fraction of the time. Every random sample in this file uses a fixed seed, so two renders of one image are identical.
- `provenance_recording.py`, `staleness.py` — the single call every pipeline makes to record its IVOA provenance (which run, at what version, produced a result — see `astrometricslib/models/provenance.py`), and the matching check for whether an already-saved result still reflects the pipeline's current version.
- `quality/` — shared quality-measurement helpers (background level, saturation, detection confidence, per-frame statistics) that more than one pipeline's own quality checks build on. `quality/quality_metrics.py` and `quality/frame_statistics.py` measure star width (FWHM, full width at half maximum) only when the caller passes a measuring function in; the public API passes the astrometry pipeline's `measure_fwhm_from_data`. `quality/raw_frame_check.py` checks raw light frames that are not in the library yet: it measures stars, trails and the move since the previous frame, and flags frames that differ from their batch (see `QualityDiagnostics.frame_quality(kind="raw_check")`). Each frame is flagged for any of these:
  - A star count below 0.5 times, or above 1.4 times, the batch median. The upper limit of 1.4 is a designed value, not one fitted to data. A count that high usually means extra bright regions that are not stars, such as a trail or a light leak.
  - A bright streak much longer than the batch's longest streak.
  - A faint straight trail, such as a satellite or aircraft, at least a quarter of the frame diagonal long (`TRAIL_MIN_DIAGONAL_FRACTION`, also an argument of `check_raw_frames`). The detector averages the frame in 4 by 4 pixel blocks, keeps blocks above 3 noise units that are not inside stars, and runs a line search (a Hough transform, which lets every bright block vote for the lines through it). The result lists the trail length in pixels (`line_trail_px`) and its angle in degrees (`line_trail_angle_deg`). It takes about 0.3 s for a 3008 by 3008 frame.
  - Stars much wider or less round than the batch's, a failed match to the previous frame's stars, or a large move since the previous frame.

  The check counts a pixel as saturated when it reaches the saturation level of the frame's camera profile (chosen from the `INSTRUME` header card). A 14-bit camera such as the Nikon D5300 clips near 16383 ADU, so a fixed 65000 would never trigger. The result records the level (`saturation_threshold_adu`) and where it came from (`saturation_threshold_source`). The check uses 65000 only when no camera profile can be read. The level logic is `resolve_saturation_threshold` in `quality/saturation.py`. It takes the saturation level from the camera profile, and falls back to the profile's clip ceiling when the profile's threshold sits above it. The spectrum check (`spectroscopy/pre_processing/spectral_frame_check.py`) uses the same function.

  The other `quality/` modules:
  - `background_measurement.py` — reads a frame from disk and measures its sky background level and the fraction of saturated pixels. The decision whether the background changed too much during a stacking run lives in `stacking/pre_processing/background_homogeneity.py`.
  - `detection_confidence.py` — `significance_to_confidence` turns a signal-to-noise ratio into a confidence score from 0 to 1 that levels off as the signal grows. It is a chosen curve, not a calibrated detection probability; a higher value means a stronger detection.
  - `frame_quality_report.py` — builds the reports that `QualityDiagnostics.frame_quality` returns for `kind="raw_check"` and `kind="input_quality"`. Each report also looks for slow drifts across the newest frames. Nothing is saved.
  - `frame_selection.py` — picks the frames a quality check measures, by filter, file-name range and time, for library frames and for a plain folder.
  - `frame_trends.py` — finds a slow, steady change in one number (sky level, star width) across recent frames, as from dew or drifting focus. It fits the median of all pairwise slopes (the Theil-Sen slope), so one bad frame cannot fake or hide a trend. It flags a trend when the fitted change, as a percentage of the starting level (`change_percent`), reaches the caller's threshold and at least 70% of the frame-to-frame steps go the same way (`STEADY_STEP_FRACTION`), with at least 4 frames (`MINIMUM_FRAMES`).

For exact behavior, read the code — the code is always the source of truth.
