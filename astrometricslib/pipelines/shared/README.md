# Shared pipeline tools

This folder holds code that more than one pipeline (astrometry, photometry, spectroscopy, asteroid detection, stacking) depends on. Nothing here runs on its own — it is called from inside a pipeline's own `pipeline.py`/`runner.py`/`batch.py`.

## What each file is for

- `analysis_context.py` — the shared container a pipeline run passes between its own stages: the loaded image, detected sources, and results found so far.
- `frame_grouping.py`, `frame_optics.py` — sort a target's frames by camera, optic, and role (light/dark/flat/bias), and work out which physical telescope or lens took a given frame.
- `frame_scanning.py` — finds image files on disk and reads them into frame records. It skips the output of processing: a file whose name contains `_stacked`, `starless`, `starmask` or `processed`, or whose header has a positive `STACKCNT` (Siril writes it only on a stack, and keeps `IMAGETYP = Light Frame` on it). The sorter files such a stack under `others`, not under the lights.
- `quarantine_path.py` — the name of the `_excluded` folder where stacking moves frames with clouds or trailed stars, and the one test for "is this path inside it". Frame scanning skips that folder so moved frames do not rejoin the target.
- `calibration_ingest.py` — turns a rescan of the calibration library into a report. It compares the library's frame lists from before and after the rescan, lists the groups that gained or lost frames, and measures each new set of flats with the stacker's own flat check (`stacking/pre_processing/flat_calibration.py`). `CalibrationCatalog.refresh` and `CalibrationCatalog.assess_flats` call it.
- `previous_stack_path.py` — the name of the `_previous` folder where a restack keeps the stack it replaced. Frame scanning skips that folder so the old stack never counts as an input.
- `session_identification.py`, `target_sessions.py` — group a target's frames into observing sessions (one continuous night or run with the same setup), and figure out which stars an image sequence contains. `session_identification.py` also holds `write_wcs_to_fits_header`, which saves a solved WCS into a FITS header. It writes the SIP distortion terms with the sky map and deletes the sky-map keywords of any earlier solve first.
- `camera_passes.py` — plans which cameras a batch run should process, and which targets go to each camera pass.
- `angles.py` — angle helpers. `wrapped_ra_difference_deg(ra1, ra2)` subtracts two Right Ascensions (RA, the east-west sky coordinate) and wraps the result into (-180, 180] degrees, so 359.9 and 0.1 are 0.2 deg apart. It accepts floats or arrays. Code that compares or searches around RA values calls it instead of subtracting, because RA wraps from 360 deg back to 0 deg. The asteroid detector and the astrometry star identifier use it.
- `catalog_star_identity.py` — decides whether two different catalog names refer to the same star.
- `star_recording.py` — the shared rule every pipeline uses to decide which stars are worth keeping, and how to save them to the star catalog.
- `applied_camera_profile.py` — records which camera profile (sensor characteristics, saturation threshold) a pipeline run actually used, on that run's quality summary.
- `target_center_hint.py` — turns a target's catalog right ascension/declination into a starting position hint for plate solving.
- `solar_system_targets.py` — tells whether a target name is a planet, the Moon or the Sun. Code that names the star at the centre of a frame skips these targets, because they have no star-catalog entry.
- `target_camera_index.py` — summarizes each target's light frames per configured camera: how many frames each camera took and the time of the newest one. The user interface's target list uses it to filter by camera and to sort by the most recently imaged. A camera writes its name into FITS headers in its own spelling (for example `Nikon DSLR DSC D5300`), so the module matches names to the configured camera names through `camera_identity`, which reads each camera profile's alternate spellings. `TargetCatalog.camera_index` calls it. A frame from a camera that is not configured still counts toward a target's newest frame time, but not toward any camera.
- `target_records.py` — reads and writes `Target` records in the catalog database. `PROCESSED_IMAGE_EXTENSIONS` lists the endings of a finished picture (`.jpg`, `.jpeg`, `.png`, `.tiff`, `.tif`); `TargetCatalog.reindex_frames` makes such a file the target's processed image instead of a frame. A process keeps one object per target: a target handed out by `get` stays the object the catalog holds, so a job that edits it for minutes (a stack) still saves its edits. `list` reads the stored targets fresh and updates a held target in place only if it has no unsaved edits. A save writes only the targets that were touched and really changed since they were read or last saved, so a copy that was only looked at cannot overwrite another program's edit. `read_saved_target` reads one record straight from storage, to check what a save wrote.
- `star_catalog_queries.py`, `star_analysis.py` — answer `StellarCatalog.query`. They pick stars by ids, name, target, region or position, filter them (magnitude, spectra, photometry, a real catalog magnitude, spectral class, a search text), hide single-frame photometry detections (ids ending in `:Star_<n>`), sort them by id, by usefulness (spectra, then named stars, then photometry, then brightest first) or by spectrum match, and page them. They also count stars per spectral class and per target. A real catalog magnitude is a finite number of at least -2 that is not exactly 0 (`has_catalog_magnitude` in `models/stellar_source.py`); smaller values are instrumental magnitudes from photometry, and 0 means the catalog gave none.
- `star_overlay.py` — places a target's stars in pixels on its stacked image, for labels drawn over it. It projects each star's sky position through the image's world coordinate system (WCS, the FITS header block that maps pixels to sky positions) and keeps the stars that land on the image. When the image has no WCS, it uses the pixel center saved when each star was detected. Star clusters and `Star_<n>` field detections get no label.
- `api_arguments.py` — checks the arguments of the public methods. `resolve_target` turns a target id into its `Target` after reading the stored targets again, so a target another program changed is seen.
- `image_conversions.py`, `image_scaling.py` — convert images between formats and adjust brightness/contrast for on-screen display. For a big frame, the display stretch measures the sky from a sample of the pixels (`measure_sky(..., sample_pixels=True)`), which gives the same picture in a fraction of the time. Every random sample in this file uses a fixed seed, so two renders of one image are identical.
- `provenance_recording.py`, `staleness.py` — the single call every pipeline makes to record its IVOA provenance (which run, at what version, produced a result — see `astrometricslib/models/provenance.py`), and the matching check for whether an already-saved result still reflects the pipeline's current version.
- `quality/` — shared quality-measurement helpers (background level, saturation, detection confidence, per-frame statistics) that more than one pipeline's own quality checks build on. `quality/raw_frame_check.py` checks raw light frames that are not in the library yet: it measures stars, trails and the move since the previous frame, and flags frames that differ from their batch (see `QualityDiagnostics.frame_quality(kind="raw_check")`).

For exact behavior, read the code — the code is always the source of truth.
