# Utilities

This folder holds small, generic helpers that several parts of the library use and that belong to no one pipeline: parsing, domain-independent algorithms, and the library's own error subclasses. The infrastructure both libraries share (configuration, enums, camera names, logging, storage, jobs) lives in `astrometricslib/foundation/` instead.

Terms are defined in the [glossary](../../documentation/Glossary.md). This document also defines each term the first time it appears.

## What each file is for

- `exceptions.py` — the error subclasses only astrometricslib raises, such as `PlateSolveFailedError`. It also names `DATA_ERRORS`, the built-in errors that measuring unusable data can raise, and `ONLINE_QUERY_ERRORS`, the errors an online catalog query (SIMBAD or Gaia) can raise. Code that measures data catches those tuples instead of every exception.
- `coordinate_parsing.py` — parses astronomical coordinate strings (right ascension and declination, the sky's equivalents of longitude and latitude) into decimal degrees.
- `observing_night.py` — names the observing night a moment belongs to: the local date on which the night began, found by subtracting 12 hours from the moment. A night that crosses midnight keeps one name, so records written before and after midnight group together. The SQL queries of wayfindinglib's `ControlRecordStore` use the same rule.
- `iso_text.py` — helpers for parsing and formatting the ISO and gain-setting text stored on a frame. ISO is a consumer camera's sensitivity setting (the header's `ISOSPEED`), named after the film-speed standard; the gain setting is the same idea on an astronomy camera (the `GAIN` card). The helpers write an ISO the same way every time (`800`, not `800.0`), so frames taken at one setting are not split into two groups.
- `camera_setting_text.py` — writes a camera's gain, offset and binning as standard text (`0`, `10`, `1x1`), so a setting stored in a camera profile and the setting a frame's header states compare equal. The calibration library has no binning rule of its own: its `normalize_binning` is this module's function.
- `concurrency.py`, `parallel_batch.py` — decide how many worker processes a batch job may run, and run the batch. `concurrency.py` takes the configured (or automatic) worker count and lowers it to what the computer's CPU count and free memory allow. `parallel_batch.py` is the engine that fans the work out. Any pipeline stage that spreads work across several processes uses them.
- `rejection_thresholds.py`, `stack_filter_floor.py` — two generic rules for small stacks.
  - `rejection_thresholds.py` sets the pixel-rejection threshold (the limit, in standard deviations, beyond which stacking throws out a pixel's value in one frame) from the number of frames. `rejection_bounds` adds a floor, because with only a handful of values per pixel the standard deviation is itself a noisy estimate. It also sets the low limit slightly looser than the high one, because bad pixels (satellite streaks, cosmic-ray hits, hot pixels) are brighter than their neighbors, not darker. The floor and the looser low limit are partly measured; see [STK-08](../../documentation/library_design/validation/stacking.md#stk-08).
  - `stack_filter_floor.py` keeps the sharpness filter from discarding too many frames. Siril can drop the blurriest frames before stacking and keep a set percentage of the sharpest. On a small batch that can leave too few frames, so this file loosens the percentage step by step until at least five frames survive (partly measured; see [STK-10](../../documentation/library_design/validation/stacking.md#stk-10)).
- `spectroscopy_models.py` — pydantic models for spectroscopy camera and session configuration.
- `target_classification.py`, `solar_system_targets.py` — read a target's kind from its name alone, with no file or database access. `classify_target_name` returns a `TargetObjectType`. The kinds are a solar-system body; a Messier, NGC or IC number (an entry in one of the standard catalogs of galaxies, clusters and nebulae, such as M 13 or NGC 2244); a comet or asteroid; a calibration folder; or a star. `Target.object_type` calls it. `is_solar_system_target` tells whether a name is a planet, the Moon, the Sun, Pluto or Ceres. Code that names the star at the center of a frame skips these targets, because they have no star-catalog entry. Both live here so the `models/` package can use them without importing pipeline code.

For exact behavior, read the code.
