# Shared quality measurements

This folder holds measurements of how good an image or a batch of frames is, independent of any one pipeline. They work on pixel data that is already loaded and own no outside resource such as a subprocess or a database file. Stacking, spectroscopy and the API layer all use them.

Terms are defined in the [glossary](../../../../documentation/Glossary.md). This document also defines each term the first time it appears.

## What each file is for

- `quality_metrics.py` — functions that measure how good an image is, such as star width (FWHM, full width at half maximum) and the count of saturated pixels (pixels at the sensor's maximum value).
- `saturation.py` — counts saturated pixels and finds the level at which a raw frame's pixels count as saturated, from the camera profile's `pixel_saturation_level_adu` (`resolve_saturation_threshold`): its saturation threshold capped at its clip ceiling. The raw frame check and the spectral frame check share it, so they agree on the level.
- `background_measurement.py` — reads image data and measures how bright the sky background is. The decision about whether the background changed too much during a stacking session lives in `stacking/pre_processing/background_homogeneity.py`.
- `frame_statistics.py` — counts the frames of a target that share the same camera settings, and measures basic per-frame statistics.
- `frame_selection.py` — chooses which frames a quality check measures, by filter, file-name range and time, for frames in the library and for frames in a plain folder. It only reads.
- `raw_frame_check.py` — the quick quality check of raw light frames before ingestion. It measures each frame's stars, sky level, saturated pixels, long straight lines from satellites or aircraft, and shift from the previous frame. It flags the frames that stand out from the batch. `detect_stars` is its star and bright-region finder, which `frame_measurement.py` also uses.
- `frame_quality_report.py` — builds the reports that `QualityRecords.measure_frames` returns (`raw_check_report` and `input_quality_report`).
- `frame_trends.py` — spots a slow, steady change in one number across a run of frames, using the median of all pairwise slopes (the Theil-Sen slope).
- `detection_confidence.py` — turns a detection's signal-to-noise into one confidence score from 0 to 1. The curve is a heuristic, not a calibrated detection probability.
- `metrics.py` — declares the frame metrics: the ones the library already measured (background level, saturated pixel fraction, Gaussian star width of the brightest stars, count of detected bright regions, sensor and focuser temperature) and the ones `frame_measurement.py` adds (Moffat star width in pixels and arcseconds, star elongation and its angle, sky rate, sky noise and read noise). The names say the estimator: for example `frame.star_width_gaussian_brightest_px` and `frame.star_width_moffat_px` are two different widths, and `frame.detected_region_count` is not a star count. Each declaration says which function computes the value and why the metric exists.
- `frame_measurement.py` — `measure_frame(path, frame, target_id, camera_profile, ...)`, the one-frame measurement. It reads the pixels once, writes nothing, and returns one `QualityMeasurement` for each frame metric: the Moffat star width (pixels and arcseconds), the star elongation and its angle, the sky in electrons per second per pixel, the sky noise and the read noise (stored as two parts), the two temperatures, and the metrics the library already had. Stars come from a 14 by 14 grid over the field, one isolated, unsaturated star per cell, with no cut on stretch. Anything that cannot be measured comes back as `not_measured` with a reason. A frame stored as color planes is measured per plane. A raw color mosaic has its star shapes measured on 2 by 2 super-pixels (widths given back in original pixels) and its sky and background measured with the color pixels mixed, and the reasons say so. The sky uses a sigma-clipped mean (`measure_clipped_mean_adu`), is stored as `assumed` for a frame with no sensor temperature, and includes dark current and amp glow. Each star row says how many detected sources each cut refused. The direction of the stretch comes from the averaged ellipticity components of the stars. A time budget (`FRAME_MEASUREMENT_TIME_BUDGET_SECONDS`) skips the slow star steps and keeps the quick header and background ones. The sky in electrons needs the bias level in ADU, which a raw frame does not state, so the caller passes `bias_level_adu` (and `bias_level_reason` when it has none, so the stored row says why). The caller also passes `clipped_zero_fraction_limit` (the stacking pipeline's `CLIPPED_FRAME_ZERO_FRACTION`), so a frame not clipped at zero may use the profile's gain and read noise from another offset (the source then says "offset fallback"). The caller also passes the Gaussian width function (`measure_gaussian_width`), because this folder may not import a pipeline. The job that calls it for every light frame is `pipelines/stacking/frame_measurement_run.py`. `detect_stars_without_shape_cut` finds stars without the roundness cut of `SourceDetector`, which would drop stretched stars; both call the star finder core in `../star_finding.py`. Two more groups of rows come from the same star fits, with no second fit. The effective star width (`frame.star_width_effective_px` and `_arcsec`) adds the blur of one square pixel to the Moffat width: `FWHM_eff^2 = FWHM^2 + c p^2`, where `p` is the pixel size and `c` is `PIXEL_BLUR_FWHM_SQUARED_FACTOR` (2 ln 2 / 3, fixed by theory, not fitted). Its uncertainty kind is `model_derived`: the error covers only the measured width, not the model term. The star width by region (`frame.star_width_center_px` and `frame.star_width_corner_<xlow|xhigh>_<ylow|yhigh>_px`) is the median width of the stars in the center block and in each corner block of the 14 by 14 grid (`FIELD_REGION_CELLS_PER_SIDE`, 4 cells per side), with a count and a bootstrap error (`measure_star_profiles`, `measure_field_region_widths`). A region with too few stars is not measured. Later readers compare each corner with the center; the rows do not judge a tilt. Both groups are a design estimate (see [AST-18](../../../../documentation/library_design/validation/astrometry.md#ast-18)). The star width, elongation and angle are a design estimate (see [AST-17](../../../../documentation/library_design/validation/astrometry.md#ast-17)). The numbers are in the Implementation paper and the validation register, not here. Each frame has a budget of CPU time (60 s, counted on the measuring thread, so waiting does not use it); when it runs out the star steps come back `not_measured` with a reason that starts "CPU time budget", and the measurement job measures the frame again on its next run.
- `frame_subject` (in `frame_measurement.py`) — the one builder of a frame's quality subject. The frame job, the quarantine rows, the stacking run's frame weight and rotation rows and the astrometry run's target-clipping rows all use it, so they share one subject id and can be joined.
- `frame_metric_set_fingerprint` (in `frame_measurement.py`) — a short code for the current set of frame metrics. The frame job stores it on each frame record (`quality_measured_metric_set`). When a frame metric is added or redefined, the code changes and the job measures each old frame once more on its next run. The sky rate, sky noise and read noise metrics were raised for the offset fallback (decision D7), so frames measured before it, which had no gain entry at their offset, are measured again.
- `metric_registry.py` — gathers those declarations and the ones in each pipeline's own `metrics.py` into one read-only registry. It refuses a duplicate name and owns the list of units a declaration may use.
- `record_measurements.py` — `record_measurements(store, measurements)`, the one gate for storing measurements. It checks each against the registry (registered metric, same definition version, an allowed subject level, a check limit in the metric's unit, no uncertainty where none is declared) and then calls the `QualityStore`. A broken rule raises `InvalidArgumentError` and nothing is stored. One exception: a row whose origin is `backfilled` may carry definition version 0, meaning "unknown (backfilled)"; a measured row never may. `astrometricslib/pipelines/test/test_metric_conformance.py` checks that every declaration points at a real function, uses a known unit, ends its name with that unit (`_px`, `_arcsec`, `_adu`, `_deg`, `_angstrom`, `_s`, `_e`, `_fraction`, `_count`, `_mag`; a unitless ratio has no ending; gates and three named Gaia XP slopes are the only exceptions), and cites a validation register entry that exists.

- `pipeline_measurements.py` — the helpers every pipeline uses to emit measurements. `make_run_id(job_id)` gives the job id, or a generated time-ordered `run-` id when there is no job. `PipelineRunContext` holds the facts one run shares (target, pipeline, version, run id, job id, `measured_at`) and builds the run subject (level `run`, id `<target>/<pipeline>/<run id>`) or a stack subject (level `stack`, id `<target>/<stack file name>`). `build_measurement` makes a `QualityMeasurement` from a metric declaration; a missing value becomes `not_measured` with a reason. A value that is present never keeps the "why it is missing" sentence a caller passed for it; only a self-check keeps its detail, and an `assumed` value keeps the source of the assumption. `gate_measurement` stores a self-check gate with its outcome and limit. `record_run_measurements` stores a batch through `record_measurements`, logs a storage failure and never raises it. `build_and_record_measurements` builds the rows and stores them inside one guard: any exception is logged with its traceback and swallowed, so a bad summary number or a changed field name never fails a science run. `build_measurement` turns a NaN or infinite value into `not_measured` with the reason "the value was not finite". `GateLimitSource` (metric, limit tier, register entry) is the row type of each pipeline's published `GATE_LIMIT_SOURCES` table, which the history fill reads. A pipeline passes `measured_at` in its request options because pipeline code never reads the clock.

For exact behavior, read the code.
