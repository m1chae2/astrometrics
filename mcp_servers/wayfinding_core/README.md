# Wayfinding MCP server

This folder exposes the Wayfinder interface (observatory control, planning, execution) as an MCP (Model Context Protocol) server, so an AI agent can call the library's tools directly. It reuses the registry and reflection engine in `mcp_servers/common/`. Run it with `python -m mcp_servers.wayfinding_core`.

## What each file is for

- `__main__.py` — the server executable.
- `definition.py` — registers every public method of the three Wayfinder branches as a tool.
- `tool_manifest.json` — the reviewed list of tools with a class, category and disposition for each. The server offers a client only the tools this file allows. See the next section.

## Which tools the server offers

When the server starts, it removes every tool that the manifest does not allow for the profile. There is one profile, `investigator`, and it offers tools that look things up, calculate or measure. It offers no tool that commands a device, changes settings, or runs code. The two syncs, `observatory_remote_sync_frames` and `observatory_remote_sync_logs` (class `ingest`), are not served here: they start a job in the app, so the `astrometrics-backend` server serves them through the app's own sync (see "Tools that start a job in the app" in `mcp_servers/README.md`). This server has no tool of class `develop` or `author`.

The rules fail closed. A tool that is missing from the manifest is not offered, so a new public method stays hidden until someone reviews it. A missing manifest withholds every tool. A tool can also carry an `interim_block`, which hides a read-only tool until a known problem is fixed.

Do not edit `tool_manifest.json` by hand. The script `python -m mcp_servers.inventory --write-runtime-manifests` writes it from the reviewed decisions. `test/test_profile.py` fails if a registered tool has no manifest entry.

## What a client sends

A client sends JSON, and the tools pass it to the Wayfinder methods unchanged. The methods accept what a client can send:

- `target`: a target id such as `"M 52"`. A remote folder name such as `"M_52"` also matches. The library reads the stored targets again before the lookup, so a target another program changed is seen. An unknown id raises `NotFoundError` with a message that names it.
- `position` and `destination` (a sky position): a dictionary `{"ra_deg", "dec_deg"}`. A dictionary that is not a position raises `InvalidArgumentError` that names the expected keys.
- `get_visibility` takes `objects` as names or ids (looked up in the library and then in SIMBAD, an online star database) or `{"id", "ra_deg", "dec_deg"}` dictionaries, and `time` and `end_time` as `"now"` or ISO 8601 strings. An offset such as `-06:00` is honored, and a string with no offset means UTC.

A slow method (marked `@background_job`) runs as a recorded job; see `mcp_servers/README.md`.

For exact behavior, read the code. The code is the source of truth.

## Tools for judging a night

These tools answer the questions that come up during and after a night of imaging:

- `visualization_render` returns a real image of a frame or stack (the image is sent as a path), with a stretch, 1200 pixels on its longest side unless asked. A crop (`crop`: the center's column and row, counted from 1, and the side) zooms on one place so trailing can be judged by eye. `visualization_plot_image` draws the same image as a figure, with `overlays` (`["detections", "stars"]`) that mark the detected stars and name the stars that have photometry. Both reply with a real image, not base64 text.
- `quality_frames_measure` measures frames. It takes a filter object (`target`, `night`, `since`, `until`, `filter_name`, `first_file`, `last_file`, or the exact `paths`; a bare number such as `013` means frame 013), built into the frame choice by `common/frame_choice_form.py`. Imaging frames get the batch check, whose answer also has `trends`: it looks at the newest `trend_frames` frames and flags a steady drift in star width, star count or sky level when it passes `trend_threshold_pct` (code in `pipelines/shared/quality/frame_trends.py`). The sky level is trended only when every frame has the same exposure, so a longer exposure is not read as a brighter sky (code in `pipelines/stacking/frame_quality_report.py`). `include=["metrics"]` adds the stored frame metric set, about 12 s a frame.
- `review_targets_get_frame_guiding` (wayfindinglib) cuts the stored guide-log samples to each frame's exposure window. The frames come from a filter (night, filter, time range); every light frame of the target when it is left out. It reports the guide error inside each window and lists the frames well above the group's median. With `include=["quality"]` each row also carries the frame's star count, star width, roundness, trail length, sky level and quality flags, so image quality and guide error sit in one table (about a second a frame, at most 60 frames).
- `review_nights_get_live_status` (wayfindinglib) reads tonight's Ekos and KStars logs (`force=true` copies the newest ones first). With `include` it adds sections of the Ekos record, such as `autofocus_runs` (with each focus curve and whether the fit succeeded), `aborted_captures`, `guide_state_events`, `mount_state_events`, `align_events` and `mount_positions` (declination, altitude, azimuth, pier side), so the cause of a flag can be read. The log records when a capture aborted but not why; the reason has to be read from the guider and mount events around that time.
- `quality_frames_measure` on spectrum frames (found by their filter) measures them: the zero-order position, the streak's tilt and width, the sky, the peaks of the zero order and the spectrum, and every saturated patch with its distance along the spectrum from the zero order (a clipped zero order is normal; clipped spectrum pixels lose data). `predict_exposure_s` scales the peaks to another exposure and says whether the spectrum would clip there. The summary groups frames by exposure length and by pier side (median, smallest and largest tilt), which answers whether the tilt depends on the side of the pier. The code is `pipelines/spectroscopy/pre_processing/spectral_frame_check.py`.
- `planning_sky_get_visibility` with an `until` time also lists `sun_events` under `night`: when the Sun reaches sunset, civil, nautical and astronomical twilight, interpolated between time steps.
- A frame sync (`observatory_remote_sync_frames`, served by `astrometrics-backend`) writes log lines and a `N of M frames transferred` progress message into its `remote_sync` job while it runs, so `jobs_get_log` and the app's job list show it moving.
- `app_status` (backend) now reports the live app: `telescope` (RA/Dec, Alt/Az, tracking or parked, ambient temperature and humidity, camera temperature and state, focuser, filter, and the mount's pier side and tracking switches read from its INDI properties), `guiding` (running, RMS, the newest 20 samples), `indi_devices`, and `indi_properties` for one `device`. It asks the backend, which holds the hardware connection. `observatory_mount_status`, `observatory_imaging_status` and `observatory_safety_status` are blocked because the MCP process has no hardware connection: their device sections would return `0`, `[]` and `unknown`, or open the connection with a device command.
- `target_query` lists the targets that match its filters (text, camera, configuration, sky region, object type) as a page of targets. The reply shaper cuts each target's frames to fit the 40,000 character reply; `target_frames_query` lists one target's frames. `target_count_by_camera` and `target_count_by_night` count frames by camera and targets by night, `target_resolve` turns a name into a position, and `target_measure_field_centers` lists the imaged sky positions.
- `star_query` lists star records without their light curves, filtered by `target`, a sky circle, magnitude, `spectral_class`, `variable`, `text`, `has_photometry`, `has_spectra` and `has_catalog_magnitude`, in `order_by` id, useful or match order. It lists 50 stars unless the client gives a `limit`, and at most 200 (`CLIENT_LIMITS` in `astrometrics_core/definition.py`); the reply cuts the spectrum points out. Single-frame photometry detections (ids ending in `:Star_<n>`) are hidden unless `include_unresolved` is true. `star_count_by_class`, `star_count_by_target` and `star_get_statistics` give the counts, `visualization_get_star_overlay` places a target's stars in pixels on its stacked image, and `star_measure_periodicity` runs the period and transit searches on one star without saving. `star_get` returns one star's record.
- `planning_catalogs_query_sources` lists library targets and stars near a point, or SIMBAD and online catalog stars, brightest first, with the total. It lists 100 stars unless the client gives a `limit`, and at most 300 (`CLIENT_LIMITS` in `wayfinding_core/definition.py`); the library lists every match by default. `target_resolve` gives the position of a name.
- `visualization_plot_target`, `visualization_plot_star`, `visualization_plot_astrometry`, `visualization_plot_photometry`, `visualization_plot_spectroscopy`, `visualization_plot_focus` and `visualization_plot_asteroids` each draw one chart and return a PNG image with the panel titles.
- Slow read tools run as background jobs: `quality_frames_measure`, `quality_stacks_measure`, `calibration_assess`, the slow `review_nights_*` reads and `review_guiding_get_night`, `target_measure_field_centers` and `planning_catalogs_predict_deep_catalog` (the size estimate of the deep-star catalog). A call that finishes within 20 seconds returns `{"jobId", "result"}`; a slower one returns a job id to follow with `jobs_get` (its `output_metrics` hold the answer when it ends). These jobs appear in the app's job history with the type `diagnostics`.
- `processing_enhancement_run` and `processing_stacking_run` start a job in the app. The `astrometrics-backend` server serves them; see "Tools that start a job in the app" in `mcp_servers/README.md`.
- `processing_stacking_get_summary` gives one short answer for a target's stack. `observatory_remote_frame_locations` counts a target's frames on the telescope, on the drive and in the library. `jobs_query` marks a job idle for over an hour as `looks_stale`. It lists 20 jobs unless asked, at most 50, without their stored numbers; `jobs_get` reads one job whole, `jobs_get_log` at most 200 log lines, `jobs_get_warnings` the checks a job failed and `jobs_get_lineage` a target's pipeline runs (`CLIENT_LIMITS` in `astrometrics_core/definition.py`).
- The `observatory_` tools follow the topic groups of `Wayfinder.control`: `observatory_mount_*`, `observatory_imaging_*`, `observatory_guiding_*`, `observatory_remote_*`, `review_*`, `observatory_safety_*` and `observatory_equipment_*`. `definition.py` reflects each group under its own prefix, so `control.mount.park` becomes `observatory_mount_park`. Each group with readable state has one `*_status` tool, whose `include` argument picks the sections of the reply. The mount's `position` and `destination` arguments take a `{"ra_deg": ..., "dec_deg": ...}` dictionary.
- `planning_sky_get_visibility` with an `until` time also lists `sun_events` under `night`: when the Sun reaches sunset, civil, nautical and astronomical twilight, interpolated between time steps.
- The other planning tools follow the four objects of `Wayfinder.planning`. `planning_sessions_get` reads one night's plan with its checklist, framing and revision (`include` adds the progress and the sample lists) and `planning_sessions_query` lists the sessions. `planning_packages_get`, `planning_packages_get_for_target`, `planning_packages_query` and `planning_packages_query_suggestion_log` read the package library, and `planning_packages_get_depth_goal` a target's depth goal. `planning_sky_get_tonight_advice` ranks targets for tonight and `planning_sky_get_panels` works out mosaic panel centers around a named object. `planning_catalogs_query` lists the online catalog drivers and `planning_catalogs_get_deep_status` reads how much of the deep-star catalog is installed. The tools that write (`planning_sessions_create`, `planning_sessions_add`, `planning_sessions_remove`, `planning_sessions_update`, `planning_packages_create`, `planning_packages_update`, `planning_packages_restore`, `planning_packages_create_mosaic`, `planning_packages_record_suggestions`, `planning_packages_set_depth_goal` and `planning_catalogs_record_deep_catalog`) are not offered to the AI. Calibration advice comes from the core's `calibration_query`.
- `review_targets_get_report` and `review_targets_get_result` (in `Wayfinder.review.targets`) judge data and results that exist. `planning_sky_get_tonight_advice` recommends what to image next. `review_targets_get_report` gives a target's dataset report: a summary for each capture setting, statements in priority order, a starting point when the target has no frames, and the check of earlier forecasts. `planning_sky_get_tonight_advice` ranks targets by the noise cut one clock hour would give, with a separate list for each use. `review_targets_get_result` says how far to trust one star's spectrum class or period. Every statement names its evidence, its limits and a confidence from the validation register, and none advises new hardware. The library returns whole statements. The tool registry shortens a long reply by trimming each statement's evidence, keeping the references furthest beyond the limit first, before its own character cut. A "take N more" count appears only after one of that target's forecast checks agreed.
- `review_nights_get` gives a night review with a loss account for each target, `review_nights_query` says which nights have guiding, capture and sky data, and `review_nights_get_target_changes` lists the slews that moved the mount to a new library target. The other night reads are `review_nights_*`, `review_guiding_*` and `review_alignment_*`, one tool per question.
- `target_frames_get_set_aside` lists the frames in a target's `_excluded` folders with the reason and where the reason came from. It moves and writes nothing.
- In monitor mode (every capability delegated) every motion, capture and stop command is refused, including `guiding:stop` and `telescope:alignment_stop`. Changing a device setting stays allowed.
