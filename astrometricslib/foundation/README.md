# Foundation

This folder holds the infrastructure that both libraries, the backend, the MCP servers and the scripts all share, so none of them has to own it. The code here imports nothing else from `astrometricslib`, `wayfindinglib` or the backend. Other code imports its names from the top-level `astrometricslib` package.

Terms are defined in the [glossary](../../documentation/Glossary.md). This document also defines each term the first time it appears.

## What each file is for

- `errors.py` — one family of errors for the libraries, the backend and AI agents, and the `ErrorInfo` record that carries an error over JSON. Each error category says what kind of problem happened and what the caller can do about it. Each also says how it is shown, `report`: `status` (something is offline or not reachable, so a status chip shows it), `error` (an action the user asked for failed) or `notify` (the user must act; a desktop notification too). And it says the level it is logged at, `log_level`: `INFO` for a missing item, `WARNING` for a bad argument, a conflict, a refused permission or a configuration problem, and `ERROR` for disk, device, outside service and pipeline failures. One error can override both through its constructor. Both travel in `ErrorInfo`, and the backend and MCP adapters log and report by them. `wrap_outside_error` puts an error from Python or another package (an `OSError`, a `ValueError` from astropy) into a category; `to_error_info` uses it for an `OSError`, with a generic message. `MovedError` (a `NotFoundError` and an `AttributeError`) is what a renamed public method raises, with "moved to ..." and the new call (see `_internal/renames.py`).
- `arguments.py` — the argument rules both libraries share, public as `astrometricslib.arguments`: `TimeInput` (a time as text, `datetime` or astropy `Time`; no zone means UTC) with `to_epoch_seconds`, and `check_choice`, `check_include`, `check_limit` and `reject_unused_arguments`. Each refuses a bad value with `InvalidArgumentError`.
- `logging.py` — one way to set up logging, a log context that tags every message with the call or job that wrote it, and the router that fills a job's own log.
- `config.py`, `config_schema.py` — the application configuration loader, and the Pydantic models (typed, validated classes) that define the configuration's structure and defaults. A save writes a temporary file and moves it over the config (`os.replace`), under a write lock (`AppConfiguration.write_lock`, a thread lock and a lock file beside the config), so a crash or a second writer never leaves a half-written file.
- `observatory_setups.py`, `observatory_site.py` — read the optics (telescopes and lenses), the camera-and-optic setups and the observatory's location from the config file. `setup_for` and `setup_for_focal_length` find a setup by camera and optic name or by camera and focal length, and take a camera-name function so that profile aliases (`ZWO CCD ASI533MM Pro` and `ZWO ASI 533MM Pro`) match. The site reader has no default site, because a made-up site would give wrong time corrections.
- `launch_identity.py` — reads the optional, read-only `[Launch]` section of the settings file. A program that starts the app (a launcher) writes it to say what kind of run this is: `label` (text for the status chip), `live_hardware`, `disposable_library`, `offline` and `locked_keys` (the `Section.key` names the settings page cannot change). `LaunchIdentity` holds the answer, and `AppConfiguration.get_launch_identity` returns it, or `None` for an ordinary run (no `[Launch]` section). The `offline` key fails closed: any value that is not clearly false (`false`, `no`, `0`, `off`) counts as offline, and a `[Launch]` section that cannot be read counts as offline. This module is the one place that parses the section. Nothing in the libraries builds or removes anything from it.
- `offline.py` — the choke point for outgoing network clients. When the launch says `offline = true`, `require_online` (an internet service) and `require_local_host` (a telescope computer reached by host name) raise `OfflineModeError`, an `ExternalServiceError` that reports as a status (logged at `INFO`) and is also a `ConnectionError`. The code that already handles an unreachable service therefore treats it as unavailable: a status, not an error. The environment variable `ASTROMETRICS_OFFLINE` set to `1` or `true` also makes the launch offline, even when the settings file cannot be read. Loopback hosts (`localhost`, `127.x.x.x`, `::1`, and the IPv4-mapped `::ffff:127.x.x.x`, with or without brackets) stay allowed, as `is_loopback_host` judges them, because the simulator's stand-ins listen there. The clients that call it are SIMBAD, the Gaia cone and reddening queries, Gaia XP downloads, the online plate solver, SkyBoT, the CDS cross-match, the deep star catalog download, the SIMBAD name and region lookups, the ssh, rsync, INDI and PHD2 links to a telescope computer, and the Drive scripts.
- `camera_names.py` — turns the several spellings of one camera name (FITS header, config file, frame record) into one form so they can be compared.
- `enums.py` — enumerations (fixed sets of named values) shared by the domain models.
- `constants.py` — numbers that several packages share and that have no better home. It holds `FULL_SCALE_COUNTS`, the stack value of a full 16-bit pixel.
- `paths.py` — names the folders for temporary working files on the local disk, and treats the two Linux spellings of a mounted-drive path as the same place. `library_folders(config_file)` reads the library, frames, stacks and wayfinding folders that any one settings file names, with the same rules as the `AppConfiguration` path getters (both call `resolve_library_setting`). The simulator layer builds its "real folders" on it.
- `astropy_setup.py` — makes astropy use its bundled Earth-rotation (IERS) table offline and loads that table ahead of first use, so a coordinate conversion never waits on a download.
- `run_abandonment.py` — lets a run that was given up on stop its own helper programs. The code that starts a run (a stack in a background thread) makes a `RunAbandonment` and binds it for that thread. Code that starts a helper program, such as Siril, registers it through `launch_registered`. When the caller gives up, `abandon` stops the process groups of that run's programs only (nothing is found by name) and later starts are refused, so the thread ends and gives its job slot back. `raise_if_abandoned` is the check that code on that thread uses to stop before it records anything. `run_registered` runs a program to the end in a process group of its own, with or without a bound run, and `stop_process_group` ends a program and every helper it started; a timeout in `run_registered` uses it. GraXpert, Cosmic Clarity, the preview's Siril and `solve-field` all run through `run_registered`. `stop_process_group` is also exported from `astrometricslib.drivers` for `wayfindinglib`. Work spread over a pool of threads or processes (the frame check, the frame measurement) is stopped by `completed_unless_abandoned`, which waits for results in steps of `CANCEL_POLL_SECONDS` (0.5 s) and checks the flag at each step, and `stopping_on_abandonment`, which cancels the items not yet started and shuts the pool down without waiting for the items in progress. A cancel is therefore seen within half a second, and at most one item per worker finishes in the background with its result dropped. The stage list (`begin_stage`) and every loop that reports progress (`LoopProgress.tick`) check the flag too, so a cancelled stack stops at its next frame or stage; a program that is running is stopped at once by `abandon`. A cancelled preview remake puts the old pictures back (`remake_stack_preview`).
- `run_tally.py` — a running total that belongs to one run (the seconds a stack waited for a free Siril slot, the tries a plate solve needed), not to the process. The code that starts the run makes a `RunTally`, binds it for its thread with `bind_tally`, and reads it back; the deep code adds to whichever tally is bound there and does nothing when none is. A thread the run starts binds the tally itself.
- `versioned_cache.py` — `VersionedCache`, the one cache for slow results. It keeps each result with the data version it was built from (see `storage/data_versions.py`) and gives it back only while that version is unchanged. It is thread safe, drops the result used longest ago when full, makes one thread build a missing result while the others wait, hands each caller its own copy, and keeps nothing when the version is unknown (`None`). Night reviews, target reports, depth goal statuses, sky models, the star overlay and the dark and bias health of `processing.calibration.assess` each hold one. It is public through `astrometricslib.drivers`.
- `parameters.py` — the registry and resolver for declared parameters (see `models/tuned_parameter.py`). `collect_parameters(package)` imports a package's modules, skipping tests and scripts, and gathers every `TunedParameter` it finds. `resolve` gives one parameter's value and where it came from: the processing settings, the equipment profile, a tuned value, or the default. A missing value falls back to the default with a notice, or raises `ParameterUnavailableError` for a parameter that must refuse (a hardware limit). The notice is not logged as a warning for each parameter. The context keeps it, and a running job collects it (`collect_default_notices`) and stores the list with the job (see `jobs/README.md`). No equipment or tuned-value provider exists yet.
- `parameter_context.py` — the context a run reads its parameters from: the config, the equipment values of the camera and optic in use, the tuned values, and the bases the run has measured (`record_basis`, such as the trail width or the line spread). Before a run measures a basis, the setup gives it (`run_bases.py`). A value that scales with a basis resolves from the setup when the run has not measured the basis yet. Only when neither knows it does the value fall back to its reference-setup value, and the notice says which of the two was missing. A worker process starts with no context, so `run_parallel_batch` binds the run's camera and optic in each worker (`bind_equipment_key`), and a worker opens one fresh context for each item (`worker_item_parameter_context`), so one frame's measured bases never reach the next frame. The worker sends its notices back with its result, and the parent adds them to the job (`note_default_notices`).
- `warn_once.py` — logs a given warning only once per run, so one config mistake met on every frame does not bury other messages.
- `jobs/` — the job framework. See [jobs/README.md](jobs/README.md).
- `storage/` — generic storage plumbing. See [storage/README.md](storage/README.md).

For exact behavior, read the code.
