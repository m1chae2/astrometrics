# Visualization

This folder renders a target's or star's stored data as plots and interactive image views: light curves, spectra, star fields, and focus history. Nothing here computes new science results. It only displays results the pipelines already produced. A light curve is a star's brightness plotted against time. A spectrum is the star's light spread out by wavelength.

Terms are defined in the [glossary](../../documentation/Glossary.md). This document also defines each term the first time it appears.

## What each file is for

- `helpers.py` — the owners of the chart methods of `astrometrics.visualization`: one function per chart (astrometry star field, photometry light curve, spectroscopy spectrum, asteroid detection tracks, one star's analysis and a combined target dashboard). A target chart reads the target's stars from the catalog storage with the star query owner (`pipelines/shared/star_catalog_queries.py`), never through the public star catalog, and can start on a chosen star.
- `image_display.py` — the owner of `astrometrics.visualization.plot_image`, which draws one image as a Matplotlib figure for scripts and notebooks, with axes that count pixels from 1. Its overlays find the stars the astrometry run's star finder detects and the stack's named stars that have photometry (by each star's `library_id` from the saved identification), labeled with the library record's name so they read as in the Astronomy Manager's lists, as Image Processing's Astrometry overlay does.
- `sky_placement.py` — places a target's stack picture on the sky for a sky chart; `get_sky_picture` is the owner of `astrometrics.visualization.get_sky_picture`. It chooses the picture (the color picture, else the preview) and the stretched stack, reads only the stretched stack's header, and maps a 17 x 17 grid of picture points to right ascension and declination with the full plate solution, including the SIP distortion terms. A picture pixel is the same pixel of the stretched stack, first row at the top. A header with only the mount's pointing is not a plate solution, so that stack is not placed. Each answer is kept until either file's modification time changes, so a sky chart that asks again reads no header.
- `focus_plots.py` — the owner of `astrometrics.visualization.plot_focus`: plots showing how well the telescope stayed in focus over a session. They use each frame's focuser temperature and position. The focuser is the motor that moves the camera along the optical axis to bring stars into focus. Each frame record keeps the focuser's position and temperature at the time of the exposure.
- `star_field_visualization.py` — the internal orchestrator for the interactive 2D star field view. It coordinates the overlay layers below.
- `interaction_handler.py` — manages mouse events and interactive state for the star field view.
- `layers/` — one file per overlay drawn on the star field. The overlays show detected stars, photometry markers, spectroscopy dispersion traces and extracted spectra, moving-object tracks, the underlying image itself, and the selected star. A dispersion trace is a line along which a grating spreads each star's light. `star_selection_overlay.py` draws crosshair markers on the star the user picked. See [layers/README.md](layers/README.md).
- `geometry.py` — geometry helpers for rotated visualization elements, such as a box or line drawn at an arbitrary angle.
- `spectroscopy_field_access.py` — reads a single field off a star's spectroscopy result. It works whether the star is a real `StellarObject` or a plain dict, so the plotting code does not need to know which.
- `visualization_config.py` — shared configuration tokens (colors, sizes, default percentiles) for the whole suite. The percentiles set the display stretch. Pixel values below the 1st percentile show as black. Values above the upper percentile (default 99.5) show as white. A few very bright stars therefore do not leave the rest of the image dark.

For exact behavior, read the code.
