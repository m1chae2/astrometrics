# Drivers

This folder holds the code that talks to something outside the pipeline logic itself: disk files, external processes, external databases, and external astronomy services. Pipelines and the API layer call into these drivers rather than opening files or databases themselves, so there is one place responsible for each outside dependency.

## What each file is for

- `image.py`, `fits_access.py` — `AstrometricsImage`, the main data container for a loaded astronomical image, and the lower-level functions that read pixel data and metadata out of a FITS file. `AstrometricsImage` fixes old-style header keywords (`RADECSYS`, a missing `MJD-OBS`) in memory only. It never rewrites a frame, so a frame on a backed-up network drive stays as it was downloaded. `fits_access.FITS_READ_ERRORS` names the errors that reading a damaged or missing FITS file can raise; code that reads a file catches that tuple instead of every exception.
- `filter_detection.py` — reads an image's settings to work out what kind of picture it is (which filter, light/dark/flat/bias).
- `interfaces/` — the abstract base classes (`*Driver`) the rest of the library uses instead of a particular program or service: `StackingDriver` (a stacking program, with the `StackSettings` it takes and the `StackRunResult` it returns), `PlateSolveDriver` (a plate solver, with `PlateSolveHeader`, a FITS header that adds two optional fields, `fit_residual_rms_arcsec` and `matched_star_count`; a driver that cannot report them returns a plain header, and `read_fit_statistics` reads both cases) `SimbadDriver` (the SIMBAD database) and `GaiaXpDriver` (Gaia DR3's low-resolution XP spectra, which the spectroscopy pipeline compares its spectra with).
- `driver_set.py` — `Drivers`, a frozen record of the plate solver, stacking program, SIMBAD driver and Gaia XP driver a caller chose, with `None` for "use the built-in one". Its `plate_solve_or_default`, `stacking_or_default`, `simbad_or_default` and `gaia_xp_or_default` methods return the chosen driver or build the built-in one. This file is the only place in `pipelines/` or `api/` that names a built-in driver class (see "Injecting drivers" below).
- `siril_stacking_driver.py` — `SirilStackingDriver`, Siril as the stacking program. It wraps `siril_interface.py` and turns Siril's files into the plain values the interface names.
- `siril_interface.py`, `siril_output_parsing.py` — runs the external Siril program to stack images, and parses the text files Siril writes describing what it did. `siril_interface.py` also writes the Siril script that builds the master calibration frames (a master is the combination of many frames of one kind) and applies them to the lights. The rules for that script are:
    - **Script start and bit depth.** Every script starts with `setext fits` and `set32bits` (`SIRIL_SCRIPT_PREAMBLE`). The second command makes Siril save 32-bit floating-point pixels. Without it, Siril uses the bit depth in the user's own preferences. A 16-bit preference rounds the normalised stack to 65536 levels, which loses faint signal and breaks the linear link between pixel value and light collected after `-norm=addscale`. The command lasts for the whole Siril session, so it comes before every `convert` and `stack` line. The calibration run and the stacking run of the phase-correlation path (see the stacking README) each start with it. Siril 1.2 and later have the command.
    - **Bias and dark masters.** Several frames are stacked with sigma rejection (`rej 3 3`), which throws out pixel values far from the rest, such as cosmic ray hits. A lone frame has nothing to compare with, so it becomes the master unchanged.
    - **Flat master.** The bias master comes off every flat, including a lone one. A flat holds the bias level (the constant offset the camera adds to every pixel) on top of the light. If the offset stays in, the master flat is too flat, the vignette (dimming toward the corners) looks shallower than it is, and the lights come out under-corrected. Several flats go through `calibrate` and `stack`. A lone flat goes through `calibrate_single`, because Siril's `convert` writes no sequence file for one frame. Without a bias master, a lone flat is used as it is.
    - **Flat check.** Before Siril builds the master flat, `assess_staged_flats` measures the staged flats with `assess_flats` (see the stacking README). It passes the camera name of the lights, so the flats' brightness is judged against that camera's clip ceiling from its camera profile.
    - **Lights.** Every light is calibrated with the dark and flat masters (and the bias master when there is no dark). A stack of one light uses `calibrate_single` for the same masters, so a lone light is not recorded as a calibrated stack without being calibrated.
    - **Matching the calibration frames to the lights.** `CalibrationLibrary` files each frame under a setting key (see `calibration_library.py` below) and picks frames for a batch of lights in `select_dark_frames`, `select_bias_frames` and `select_flat_frames`. `build_directories` calls them with the batch's gain, offset, binning (read from the first readable light's `XBINNING` and `YBINNING`), exposure and mean `CCD-TEMP`. Each call returns the frames and two lists of one-sentence flags. The driver copies them into `last_run_diagnostics`:
        - `calibration_mismatch_flags` (soft). The frames are still applied. One sentence says that no frame matched the lights' gain and offset and names the gain and offset that were applied and the lights they were applied to, or that no dark was within 3 C (`DEFAULT_DARK_TEMPERATURE_TOLERANCE_C`) of the lights and names the lights' temperature, the master's temperature and the tolerance.
        - `calibration_match_blocking_flags` (blocking). No frame of that kind is applied. One sentence says that the lights' binning has no calibration frames, and names the binning that the library holds. Frames binned differently have different pixels, so they cannot calibrate the lights.

      The stacking pipeline reads both lists and fails its `calibration_metadata` gate (see the stacking README). A kind of calibration frame that the library does not hold at all raises no flag.
    - **Frame counts.** A master built from fewer frames than `minimum_calibration_frames` (default 3, in `[Processing.Siril]`) is still built, because the library can legitimately hold a single flat or dark. The run records one sentence per short master in `last_run_diagnostics["calibration_blocking_flags"]` and logs a warning. The stacking pipeline reads that list and fails its `calibration_frame_count` gate (see the stacking README), which flags the stack. The stack is flagged because the reader needs to know the masters are weak, not because the pixels are unusable.
- `astrometry_net_driver.py` — `AstrometryNetPlateSolveDriver`, Astrometry.net as the plate solver: figures out exactly what part of the sky an image shows. The local `solve-field` program writes a `.corr` table next to its solved image. Each row is one field star that the solver matched to a reference star, with the field star's fitted sky position (`field_ra`, `field_dec`) and the reference star's sky position (`index_ra`, `index_dec`), in degrees. `read_corr_fit_statistics` opens that table (with `memmap=False`), drops rows with a missing position, and returns two numbers: the fit residual (the root mean square of the sky distance between each pair, in arcseconds) and the matched-star count. The driver returns them on a `PlateSolveHeader` (see `interfaces/`). The online service writes no match table, so an online solve returns a plain header and the statistics read as unknown (`None`).
- `gaia_xp_driver.py` — `AstroqueryGaiaXpDriver`, the Gaia XP driver. It downloads the sampled XP spectrum of a Gaia DR3 source with astroquery (336 to 1020 nm in 2 nm steps, flux in W m⁻² nm⁻¹) and keeps each answer in one compressed `.npz` file per source id, with the download date, in `<library>/catalogs/gaia_xp/`. That is the same location rule as the Gaia star cache in `catalog_store.py`. A source without an XP spectrum is cached as empty. A failed download gives `None`, is logged once and is not cached, and the driver then skips downloads for 10 minutes. It never raises into a pipeline.
- `astroquery_simbad_driver.py` — `AstroquerySimbadDriver`, the SIMBAD driver. It owns the process's one astroquery client for the external SIMBAD astronomical database. A failed query is raised as `ExternalServiceError`.
- `camera_profile_store.py` — finds and loads the stored profile (sensor characteristics, saturation threshold) for a given camera.
- `calibration_library.py` — the model describing the library of dark/bias/flat calibration frames, and the rules that pick frames for a batch of lights. It can also list the flats as sets, one per telescope, camera, filter, gain, offset and binning (`list_flat_groups`), so each set is checked on its own. Each frame is filed under a setting key, built by `calibration_setting_key` and written `gain[@offset=N][@bin=AxB][@temp=T]`:
    - **Gain and offset.** A frame at one gain or offset cannot calibrate lights at another. A key with no `@offset` means offset 0.
    - **Binning** (`XBINNING`, `YBINNING`). Binning merges neighbouring pixels, so a 2x2 frame has different pixels from a 1x1 frame. Darks, bias frames and flats all key on it. A key with no `@bin` means 1x1, which is also what a header with no binning cards gets.
    - **Temperature slot** (darks only). The dark's `CCD-TEMP` (or `SET-TEMP` when there is no `CCD-TEMP`) rounds to `round(T / tolerance) * tolerance`, with the tolerance `DEFAULT_DARK_TEMPERATURE_TOLERANCE_C` (3 C). Dark current changes with temperature, so darks in different slots never stack into one master. With the default tolerance, -10.2 C and -9.0 C share the -9 C slot, and +5 C is in the +6 C slot. Bias and flat frames have no temperature slot.
    - **Exposure** (darks only). The exposure is the level below the key. A dark matches the lights when their exposures differ by less than 0.1 s.
    - **Readout mode.** The key has no readout mode. The ZWO ASI533MM Pro frames in the sample data carry no readout-mode card, so there is nothing to read.

  Picking darks works in this order: exposure, binning (exact, otherwise blocked), gain and offset (otherwise the other settings, with a soft flag), then temperature. The slot nearest the lights' temperature wins, and the colder slot wins a tie because a warmer dark over-subtracts. The library then reads the `CCD-TEMP` of every dark in that slot, not only the first, and compares their mean with the lights' temperature. It flags the master when the two differ by more than the tolerance. When the lights record no temperature and the darks span several slots, the slot with the most darks wins, with a soft flag. Darks with no temperature are used only when no dark has one. A rescan (`refresh_dark_frames`, `refresh_bias_frames` and `refresh_flat_frames`) moves a frame filed under an older, shorter key to its new key, so a library saved before binning and temperature were tracked updates on its next rescan. Until then its darks count as 1x1 with no temperature.
- `local_database.py`, `catalog_store.py` — the local SQLite databases holding the target/star catalog and the cached Gaia star catalog. The Gaia cache stores each star's epoch 2016.0 position, G magnitude, designation and proper motion (`pmra` includes the cosine of the declination; `pmdec`; both in milliarcseconds per year). A cache file written before the proper motion columns existed gets them added when it is next opened, and its old rows read as `None` (unknown). Callers that ask `query_gaia_sources_in_bounds` for `include_proper_motion` get the two values at the end of each row. The cache also keeps a `gaia_cache_regions` table: one row per downloaded region with its centre, radius, magnitude limit and whether the download hit the row limit. A request is answered from the cache only when a recorded region covers the whole request, is at least as deep, and was not truncated; otherwise the pipeline downloads. A cache written before this table existed holds rows of unknown depth, so each region is refreshed once and then recorded.
- `catalog_access.py` — reads and writes catalog data (targets, stars) to and from the local database.
- `provenance_store.py` — repository for the IVOA provenance graph (which run, at what version, produced a result — see `astrometricslib/models/provenance.py`), stored next to the job records (`astrometricslib/foundation/jobs/`) in `astrometrics_log.db`.

## Injecting drivers

A caller replaces a built-in driver by passing a subclass of `PlateSolveDriver`, `StackingDriver`, `SimbadDriver` or `GaiaXpDriver` to `Astrometrics(...)` (`plate_solve_driver=`, `stacking_driver=`, `simbad_driver=`, `gaia_xp_driver=`). `Astrometrics` wraps them in a `Drivers` and hands that to the sub-APIs, which pass it to the pipelines. See `api/README.md` for which calls use which driver.

To add a pipeline step that needs a driver:

1. Take a `drivers: Drivers | None = None` keyword.
2. Ask `(drivers or Drivers())` for the driver, for example `.simbad_or_default()`.
3. Do not import or call a built-in driver class in `pipelines/`. `test/test_driver_construction.py` fails if a pipeline module does.

A built-in driver class is not exported from the package root. Code outside the library cannot import `astrometricslib.drivers` (ruff's `TID251` ban in `pyproject.toml`), and code inside it goes through `Drivers`.

For exact behavior, read the code — the code is always the source of truth.
