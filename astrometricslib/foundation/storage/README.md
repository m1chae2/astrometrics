# Storage

This folder holds the generic storage plumbing that both libraries share. Nothing here knows about telescopes, targets or stars. It only knows about databases, locks and drives.

Terms are defined in the [glossary](../../../documentation/Glossary.md). This document also defines each term the first time it appears.

## What each file is for

- `local_database.py` — opens and writes SQLite database files on this computer (`connect_db`), and holds the JSON encoder for values SQLite has no column type for (`safe_json_dumps`, `NumpyEncoder`).
- `butler.py` — `Butler`, a generic keyed-model store. It records Pydantic model instances to SQLite tables by id, with get, put and exists operations. Both libraries instantiate it for their catalog and record data. `select_where` reads one ordered page of rows that satisfy a SQL condition, and `count_where` counts such rows. The database filters, orders and cuts the page, so only the rows of the page reach Python. Library code writes the SQL text, and every value that comes from a caller goes in as a parameter. A caller that lists a large table, such as the star catalog, uses these two instead of loading every row.
- `data_versions.py` — one small counter per kind of library data (`targets`, `quality`, `stars`), kept in a table named `data_versions` in `astrometrics.db`. Every writer adds one to its counter in the same database transaction as its write: the `Butler` when its `DatasetSpec` names a `data_version_kind`, and the quality store. A cache reads the counters (`get_library_data_version`, public through `astrometricslib.drivers`) to learn whether anything it was built from changed. Because the counters are in the file, a write by another program counts too. A write made by raw SQL that does not call `bump_data_version` is not seen, and neither is a database file swapped for an older copy, so restore a backup only while the app is stopped. Stack records and frame records live inside the target documents, so they count as `targets`; the rows that record set-aside frames are quality rows. Evidence for the version of a night review and a target report: [validation register](../../../documentation/library_design/validation/wayfinding.md), WAY-D102 and WAY-D104 (Design estimate, with a measurement on a copy of the real library).
- `process_locks.py` — file locks the operating system enforces, so two programs cannot use the same resource at once (`file_lock`, `acquire_resource_slot`). The resources include a telescope mount, a camera or a copy of Siril. Waiting for a slot has no time limit. A slot also gets a small record next to its lock file, naming the process and the work that holds it. A waiter logs who it is behind every five minutes (`describe_slot_holders`). The record is only for people reading logs: the lock alone decides who holds a slot, and a record left by a dead process is not reported.
- `mount.py` — `require_mounted_storage` refuses to write below the `frames_mount_point` setting unless a drive is mounted there. When the setting is empty, nothing is checked.

For exact behavior, read the code.
