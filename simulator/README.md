# Simulated observatory

This folder holds a telescope that is "on" without a telescope. The app uses it for its **Simulated** observatory source (Settings, Observatory). The technical performance measure (TPM) harness in `build/tpm/` uses the same pieces, and also plays back a past night (`--observatory replay`). Every piece runs on this computer.

| Module | What it does |
| --- | --- |
| `observatory.py` | `SimulatedObservatory` makes the folders and settings, checks them, and starts and stops the stand-ins. It is also a program: `python -m simulator.observatory start` or `stop`. `prepare_offline_world` builds a world with no telescope at all. |
| `library_copy.py` | A temporary, copy-on-write view of your real library for the app: database copies (SQLite online backup) and a `fuse-overlayfs` overlay of the frames and stacks. |
| `supervisor.py` | Runs one stand-in and ends it, with its children, when the process that started it ends. |
| `mock_phd2.py` | The stand-in PHD2. It plays PHD2's event stream from a guide log. |
| `exposure_driver.py` | Connects the INDI simulators and takes exposures into the stand-in telescope computer's picture folder. |
| `replay_driver.py`, `night_replay.py` | Harness only: play back a past night from the real library and logs (read only). Copied frames carry `ORIGIN = 'ASTROMETRICS-SIMULATOR'`. |
| `guide_log_replay.py`, `guide_log_sample.txt` | Turn a guide log into PHD2 events and paced log lines. |
| `observatory_guard.py` | Refuses settings that point beyond this computer or at a real library folder. |
| `simulated_calibration.py` | `record_simulated_calibrations` records a guider calibration and focus model for the simulator, from your real data, so the library's rules let capture, focus and guiding through. |
| `launch.py` | The launcher: `python -m simulator.launch`. Builds the world, runs the backend as its child, plays the operator step, guards the connections and tears the world down. See "The launcher". |
| `source_choice.py` | Re-exports the saved observatory source choice and the shared launch names from the core, and adds the names only the layer uses. |
| `connection_guard.py` | Lists the TCP connections of a process and its children that go beyond this computer. The launcher and the TPM seal guard use it. |
| `rpc_client.py` | Calls the backend's `/api/rpc` and `/api/ready` on 127.0.0.1. The launcher and the TPM scripts use it. |
| `settings.py` | The settings text that points the app at the stand-ins, or at nothing (offline). |
| `standin_ssh.sh` | An `ssh` stand-in that runs the command in the stand-in home folder. With `ASTROMETRICS_STANDIN_SSH_MODE=refuse` it refuses every connection. |

## The launcher

`python -m simulator.launch` starts the backend for you in the world the saved Observatory source names. `build/linux/run_backend.sh` always runs it (see `build/linux/README.md`). The backend builds no world: it reports the launch (`[Launch]` in the settings) and, when you change the source, saves the choice and exits with code 75. The choice file code is in the core (`astrometricslib.foundation.source_choice`, public through `astrometricslib.drivers`); `source_choice.py` re-exports it. Started without the launcher (the TPM harness, Electron's own start in the packaged app), the backend runs on the real telescope or the world its environment names and cannot change its source.

A session goes like this:

1. **Choice.** The launcher reads `observatory_source.json` from your real settings folder (`source_choice.py`).
2. **Real choice.** It runs the backend as a child with your environment, plus `ASTROMETRICS_LAUNCHER=1`. It builds no world. If no other launcher holds the simulator folder, it first removes what a crashed session left there.
3. **Simulated choice.** It takes an exclusive, non-blocking `flock` on `<simulator folder>/launcher.lock` and holds it until the world is gone. If another process holds it, the launcher touches nothing, says so, and exits with code 73. Then it builds the world (`SimulatedObservatory.prepare`: the database copies and the overlay), starts the stand-ins and waits until they are up, works out the calibration records in a short process (`python -m simulator.simulated_calibration`) while nothing else uses the copy, and runs the backend with the world's `ASTROMETRICS_CONFIG`, `XDG_*` folders and `PATH` (the ssh stand-in). The backend also gets `ASTROMETRICS_OBSERVATORY_SOURCE=simulated`, `ASTROMETRICS_SIMULATOR_ROOT` and the `ASTROMETRICS_REAL_*` folders, so it still finds your real choice file. It also gets `ASTROMETRICS_LAUNCH_MISSING_PROGRAMS`, so the settings control can say what the simulator lacks. The backend never starts or stops anything of the world.
4. **Failure.** If the world cannot be built or started, the launcher builds the offline world (no telescope, a refusing `ssh`) in the same folder and runs the backend on it. The reason reaches the backend in `ASTROMETRICS_OBSERVATORY_SOURCE_ERROR`, so `observatory:get_source` reports `SIMULATOR FAILED` and the reason.
5. **Operator step (decision D11).** When `/api/ready` answers, the launcher calls the backend's RPC methods in this order: `target:create` for the pointed target if the library lacks it, `observatory:record_guider_calibration`, `observatory:record_focus_model` and `observatory:enter_controller_mode` with `shadow_first=true`. Each log line starts with `OPERATOR STEP (D11)`, and the log lists the capabilities that are on and the ones that stay off with their reasons. A failed call is logged and the step goes on. The step runs only for a simulated world. It goes away when the app can command PHD2 and the camera itself.
6. **Connection guard.** Every 5 seconds the launcher lists the TCP connections of the backend and its children. A connection to an address beyond this computer stops the backend, tears the world down and ends the launcher with code 70. A `--lan` backend with a phone connected would trigger it.
7. **Ending.** When the backend exits, the launcher stops the stand-ins, removes the library copy, releases the lock and exits. Exit code 75 means "the Observatory source changed": the launcher reads the choice again and starts the next session, after the old world is gone. Any other code ends the launcher with that code. SIGTERM or SIGINT stops the backend first (SIGKILL after 30 s), then tears down, and exits with 0.

Two limits. `observatory:get_source` shows `commands: null`, `running: false` and `library_copy: {}`, because the backend does not know about the stand-ins; the log has the operator step's result. INDI servers share one local socket (`@/tmp/indiserver`), so a second simulator cannot start while another INDI server runs on the same computer; the launcher then falls back to the offline world.

## The library copy

- The databases are copied at switch time and at every launch of the app in a simulator source, one thread per database, so the copy takes about as long as the biggest database. Each table is scanned once to fix its paths (the copy time is in `observatory:get_source`, `library_copy`). The report's `bytes` are the final sizes of the copies, measured after the paths are rewritten and the write-ahead log is merged into the file. Paths inside the copies that name your real frames or stacks folder point at the overlay.
- The overlay's lower layer is your real folder (read only). Every write lands in `<root>/overlay/upper`. A stacks folder inside the library shares the library's overlay; a separate one gets its own.
- Leaving the mode, or stopping the app, unmounts the overlay and deletes the upper layer and the copies, only inside the simulator folder. A start in Real mode removes what a crash left (the launcher does it, while it holds the lock).

## Safety

- Commands are allowed for the simulated telescope (`allow_commands = "true"` in `SIMULATED_TELESCOPE_SETTINGS`), because the devices are stand-ins on this computer. When the simulator is up, the launcher's operator step puts the app in controller mode through the RPC (`control.safety.enter_controller_mode(shadow_first=True)`: the correction capabilities are first moved to SHADOWED, the step the rules need). The library's rules still apply. Before the hook takes control it calls `record_simulated_calibrations`, which saves a guider calibration and a focus model into the simulator's own wayfinding library (a copy of yours, made at each start), so every capability can become AUTHORITATIVE. Each value comes from the first source that has it: (1) your newest real record in the library copy, copied under the active equipment names; (2) for the guider, your real guide-log runs (the guide camera's plate scale, and the median calibrated RA and Dec speeds of the last 20 runs that look sensible, 1.5 to 15 arcsec/s), or else the active equipment's plate scale; (3) the INDI simulators' behavior (guide rate 7.52 arcsec/s, camera angle 0, a focuser with no backlash or thermal model). The records are redone at every start, so they follow new real data. Each record's `source_note` starts with `Simulator:` and names its source. The function refuses to run unless the wayfinding library is inside the simulator folder and is not one of your real folders, and it only reads the library it is given. The log lists what stays off; the backend does not report it (`commands` is `null`). The operator step never runs for the real telescope or the offline world, which keep monitor mode. The offline settings keep `allow_commands = "false"`.

- Every settings file the layer writes carries a read-only `[Launch]` section (the launch identity, see `astrometricslib/foundation/launch_identity.py`). A simulated observatory says `label = "SIMULATOR"`, `live_hardware = false`, `disposable_library = true`, `offline = true`, and locks the endpoint keys (`Observatory.Telescope` host, INDI port, picture folder and `allow_commands`; `Observatory.Guiding` PHD2 port and location; the image, frames, stacks and wayfinding folders). The offline world says `SIMULATOR FAILED`, with no hardware and `offline = true`. The backend only reports it (`launch` in `observatory:get_source`). The libraries honor `offline = true` in every outgoing client, and the settings service refuses a save that changes a locked key (`SIMULATED_LOCKED_KEYS`, `launch_section_text`, `with_launch_section` in `settings.py`).
- The INDI server and the stand-in PHD2 use free ports on this computer, never 5000, 4400 or 7624.
- `SimulatedObservatory.prepare` refuses a settings file with a host other than `127.0.0.1` or `localhost`, another port, a picture folder outside the stand-in home, any other IP address in the file, or an image library, frames, stacks or wayfinding folder that is outside the simulator folder or is one of your real folders.
- The app checks every settings save against the same rules while a simulator runs (`check_settings_update`).
- If the simulator cannot start, the app runs offline: no telescope, no PHD2, no downloads. It never falls back to the real telescope.
- Every process starts through `supervisor.py`, so none outlives the app, even after a crash. The harness starts them with the same program.

For how the app switches source, read `backend/observatory_source.py` and `backend/services/observatory/observatory_source_service.py` (the backend's side: report, save, exit 75) and `launch.py` (the launcher). For the harness, read `build/tpm/README.md`.
